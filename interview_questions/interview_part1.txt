1. What are the advantages of a Playwright?
Answer:
1. Cross-browser testing: Playwright supports multiple browsers, including Chromium, Firefox, and WebKit, allowing you to test your web applications across different platforms.
2. Auto-waiting: Playwright automatically waits for elements to be ready before performing actions, reducing the chances of flaky tests.
3. Headless mode: Playwright can run browsers in headless mode, which is faster and more efficient for automated testing.
4. Network interception: Playwright allows you to intercept and modify network requests, enabling you to test various scenarios such as simulating slow network conditions or mocking API responses.
5. Parallel testing: Playwright supports running tests in parallel, which can significantly reduce the overall test execution time.
6. Rich API: Playwright provides a comprehensive API for interacting with web elements, making it easier to write complex test scenarios.
7. Cross-platform support: Playwright can be used on various operating systems, including Windows, macOS, and Linux.
8. Continuous Integration (CI) support: Playwright integrates well with CI/CD pipelines, allowing you to automate your testing process and ensure the quality of your applications.
9. Open-source: Playwright is an open-source project, which means it has a large and active community contributing to its development and providing support.
10. Easy to set up: Playwright has a simple setup process, making it easy for developers to get started with automated testing quickly.

2. What are the browsers supported by Playwright?
Answer:
1. Chromium (Google Chrome, Microsoft Edge)
2. Firefox
3. WebKit (Safari)

3. How do you launch a browser in Playwright?
Answer:
You can launch a browser in Playwright using the `playwright` library. Here's an example of how to launch a Chromium browser:
```typescript
const { chromium } = require('playwright');

(async () => {
  const browser = await chromium.launch();
  const page = await browser.newPage();
  await page.goto('https://example.com');
  await browser.close();
})();
```
4. What are the locators in the Playwright?
Answer:
1. CSS Selectors: You can use CSS selectors to locate elements on the page. For example: `page.locator('button.submit')`.
2. XPath: Playwright supports XPath for locating elements. For example: `page.locator('//button[text()="Submit"]')`.
3. Text: You can locate elements based on their text content. For example: `page.locator('text=Submit')`.
4. Role: You can locate elements based on their ARIA roles. For example: `page.locator('role=button[name="Submit"]')`.
5. Test ID: You can use custom data attributes to locate elements. For example: `page.locator('[data-testid="submit-button"]')`.
6. Label: You can locate form elements based on their associated labels. For example: `page.locator('label:has-text("Username")')`.
7. Alt Text: You can locate images based on their alt text. For example: `page.locator('img[alt="Logo"]')`.
8. Placeholder: You can locate input fields based on their placeholder text. For example: `page.locator('input[placeholder="Enter your name"]')`.
9. Role and Name: You can locate elements based on their ARIA role and name. For example: `page.locator('role=button[name="Submit"]')`.

```typescript

(async () => {
```

20. What is Visual Testing? Why do we need it?
Answer:Visual Testing is a type of testing that focuses on verifying the visual aspects of a web application, such as layout, design, and user interface elements. 24. What are the different assertions in Playwright? (read at https://playwright.dev/docs/test-assertions)
Answer:Playwright provides various assertions for validating different conditions in your tests. Some of the common assertions include:
1. `toBeVisible()`: Asserts that an element is visible on the page.
2. `toHaveText()`: Asserts that an element has specific text content.
3. `toHaveAttribute()`: Asserts that an element has a specific attribute with a given value.
4. `toHaveClass()`: Asserts that an element has a specific class.
5. `toHaveCount()`: Asserts that a locator has a specific number of elements.
6. `toHaveValue()`: Asserts that an input element has a specific value.
7. `toBeChecked()`: Asserts that a checkbox or radio button is checked.
8. `toBeDisabled()`: Asserts that an element is disabled.
9. `toBeEditable()`: Asserts that an element is editable.
10. `toHaveStyle()`: Asserts that an element has specific CSS styles.
11. `toHaveScreenshot()`: Asserts that an element matches a baseline screenshot.
12. `toHaveURL()`: Asserts that the page has a specific URL.
13. `toHaveTitle()`: Asserts that the page has a specific title.
14. `toHaveSelector()`: Asserts that an element matching a specific selector exists on the page.
15. `toHaveTextContent()`: Asserts that an element has specific text content, ignoring whitespace and line breaks.
